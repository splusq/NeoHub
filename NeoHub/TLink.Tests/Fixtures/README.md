# Captured panel traffic

Real ITv2 traffic between a DSC PowerSeries Neo panel (TL280E, Type 2 encryption) and NeoHub,
recorded from a production install and **sanitized**. These files are the ground truth the
redesigned protocol core and panel state are tested against.

## Files

One file per panel connection, `connection-NN.jsonl`. Each line is one event, in order:

| `kind` | Fields | Meaning |
|---|---|---|
| `connect` | `ms` | The panel opened a TLink connection. `ms` is milliseconds since this event. |
| `packet` | `ms`, `dir` (`rx` from the panel, `tx` to it), `type`, `frame`, `roundTrips`, `redacted?`, `dropped?` | One ITv2 packet, decrypted. |
| `client` | `ms`, `request` | A WebSocket client request (Homebridge), e.g. `ArmHomeMessage`. |
| `operation` | `ms`, `operation` | A NeoHub-initiated operation (bypass, configuration pull, user read). |
| `marker` | `ms`, `label` | A note about what a person did at that moment ("HomeKit: arm stay"). |
| `disconnect` | `ms` | The connection ended. |

`frame` is the complete ITv2 packet as hex: `[length 1–2 B][sender seq][receiver seq][command 2 B][payload][CRC16]`,
exactly what `ITv2Session` encrypts or decrypts. Encrypted wire bytes and TLink headers are not included.

`roundTrips` says whether today's codec (`MessageFactory`) re-encodes the decoded message to the
same bytes. It is `false` for `NotificationDateTimeBroadcast`, `ProgrammingLeadInOut`, and combined
packets that contain one: the codec drops the 5-byte panel timestamp at the end of these. That is a
known codec bug, tracked by `CodecGoldenTests.KnownLossyTypes_AreExactlyTheDocumentedOnes`.

## What's in connection-01

NeoHub restart → handshake (OpenSession / RequestAccess both ways) → 2 s message burst →
capabilities → installer configuration read (29 sections) → partition and zone status, then:
arm stay from HomeKit (plus a duplicate arm the panel rejects with `FunctionNotAvailable`),
disarm, zones 1 and 9 opening and closing, bypass and unbypass of zone 16 from the NeoHub UI,
a full user read (labels, codes, attributes, partition assignments), heartbeats and date/time
broadcasts. Markers in the file label each step.

## Sanitizing

Generated by `tools/CaptureTool` from a private Trace capture (`docker logs` of NeoHub with
`Logging:LogLevel:DSC.TLink=Trace`). The raw capture contains alarm codes and names and never
enters this repository.

- Messages are decoded with the production codec, secrets replaced, and re-encoded (the CRC is
  recomputed), so redacted frames are still valid protocol bytes. Only messages that round-trip
  exactly are re-encoded.
- Replaced: arm/disarm/programming access codes and every code in `AccessCodeReadResponse`
  (each digit → `0`, length kept); user/zone/partition labels in `NotificationLabelText` and in
  installer label sections (→ `Zone 07`, `Partition 01`, `User 12`); the panel's `DeviceID` (→ zeros).
- Kept verbatim: message types on an explicit allowlist that carry no secrets. Anything else is
  dropped (`dropped: true`, sequence numbers kept), and unknown installer sections are dropped too.
- Times are offsets from each connection's start; no dates.
- The tool then audits its own output: every original code and name it replaced, and the panel's
  integration ID, are searched for as ASCII, UTF-16BE and BCD in every frame and in the JSON text.
  Any hit fails the run and deletes the output.

Regenerate (the panel ID is passed only for the audit):

```bash
NEOHUB_PANEL_ID=<integration id> dotnet run --project tools/CaptureTool -- \
  fixtures NeoHub/TLink.Tests/Fixtures <private>/markers.txt <private>/neohub-*.log
```
